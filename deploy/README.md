# Веб-сборка и публикация тестовой версии

Проверенный редактор — Godot 4.6.3. Установите экспортные шаблоны той же версии на машине сборки. VPS обслуживает только статические файлы.

## Сборка

Из каталога проекта:

```sh
./deploy/build.sh ../web-001
```

Команда импортирует проект, использует пресет Web и проверяет выходные файлы. Её можно вызвать из CI, передав уникальный идентификатор сборки в имени каталога.

## Первый запуск

1. Проверьте, что каталог `/opt/mechanic-petersburg` и файл сайта ещё не существуют, а TCP-порт 8083 свободен. Проверьте бюджет диска и памяти. При выборе другого свободного порта задайте `MECHANIC_PORT` для Compose и исправьте конфигурацию сайта.
2. Поместите `compose.yaml`, `nginx.conf` и `publish-local.sh` в `/opt/mechanic-petersburg`. Поместите содержимое сборки в `/opt/mechanic-petersburg/public/releases/001/`. Каталоги должны быть доступны для чтения и прохода пользователю контейнера (UID 101), а файлы — для чтения.
3. В `/opt/mechanic-petersburg` выполните `./publish-local.sh 001`, `docker compose config -q` и `docker compose up -d`. Проверьте `curl -fsSI http://127.0.0.1:8083/` и `curl -fsSI http://127.0.0.1:8083/index.wasm`. У WASM ожидается `Content-Type: application/wasm`.
4. После согласования применения конфигурации общего прокси добавьте только файл `/opt/konstruktor-proxy/sites/mechanic-petersburg.caddy`. Выполните в `/opt/konstruktor-proxy` команду `docker compose exec -T caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`. Если валидация успешна, выполните `cd /opt/konstruktor && ./deploy.sh proxy-reload`. Проверьте HTTPS-адрес и загрузку билда в Safari на iPhone.
5. Перед подключением CI выберите отдельный способ доставки артефактов с правом записи в каталог этого проекта. Используйте команду публикации только после полной передачи файлов.

## Следующие релизы и откат

Каждая сборка размещается в новом каталоге `public/releases/<ID>`. Команда `./publish-local.sh <ID>` атомарно переключает ссылку `public/current`. Для отката передайте ID предыдущей сборки. Обновления не требуют перезапуска Nginx или перечитывания Caddy. Публикуйте релизы последовательно, чтобы более ранняя сборка не перезаписала результат более новой. После обновления во время загрузки перезагрузите страницу. Для экономии диска оставляйте текущую и предыдущую сборки, удаляя только более старые каталоги этого проекта.
